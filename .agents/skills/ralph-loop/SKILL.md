# Ralph Loop

This skill implements a disciplined, single-step workflow for incremental development. It processes task markers (TODO, FIXME, or markdown checkboxes), executing one task at a time and stopping, enabling focused, verifiable progress through complex work packages.

## Input

The argument can be either:
- An absolute path to a working document file (markdown format with checkboxes like `- [ ] task`)
- An absolute path to a source code file (containing TODO/FIXME markers)
- An absolute path to a directory (scans for TODO/FIXME markers in all source files recursively)

Task markers include:
- Markdown checkboxes: `[ ]` for open, `[x]` for done
- TODO comments: `// TODO`, `/* TODO */`, `# TODO`, etc.
- FIXME comments: `// FIXME`, `/* FIXME */`, `# FIXME`, etc.
- Any other marker specified in the prompt

Markers are deleted or updated to `[x]`/done upon successful completion.

## Behaviour

0. Prepare for work in this repo
- Run script `./context.bat`
- Invoke skill /zig-coding

1. Determine input type:
   - If directory: recursively scan for TODO/FIXME markers in source files
   - If markdown file: parse for checkbox markers
   - If source file: scan for TODO/FIXME markers
2. Check Status
   - Collect all task markers with their location (file, line number)
   - Sort tasks by file path and line number
   - Identify the first open task
3. Execute that **single** task
4. Verify the whole codebase with `verify_all.bat` and fix.
5. Update the task's progress marker:
   - For markdown checkboxes: change `[ ]` to `[x]`
   - For TODO/FIXME: remove the marker line or comment
   - Or as specified in the prompt
6. Save the updated file
7. Commit modified files (leave other files alone)
8. Stop and report completion

## Output

- Updated file (document or source code) with the task marker marked as done or removed
- Summary of what was accomplished
- Any artifacts generated by the task execution

## Example Formats

### Markdown Document Format
```markdown
# Working Document

## Specification

- Implement feature X with constraints Y and Z

## Tasks
- [ ] Task 1: Design API interface
- [x] Task 2: Implement core logic
- [ ] Task 3: Write unit tests

## Tests
- [ ] Test 1: Verify basic functionality
- [ ] Test 2: Edge case handling

## Code Smells
- [ ] Potential memory leak in module A
- [ ] Duplicate code in functions B and C
```

### Source Code TODO Format
```zig
// TODO: Implement error handling for edge cases
fn processData() void {
    // FIXME: This is a workaround, needs proper fix
    // TODO move to file_names.zig, pass allocator directly
}
```

## Process

1. **Check Status**: Scan the input (file or directory) and identify the FIRST task marker that is NOT marked as done

2. **Stop Condition**: If ALL task markers are already done or no markers found, report completion and stop

3. **Understand Task**: Read the description and context of the identified task marker from its location

4. **Execute Task**: Perform the work required by that single task

5. **Verify**: Confirm the task was completed successfully

6. **Document Completion**: Update the file containing the task marker to mark it as done or remove it

## Execution Flow

```
Start -> Determine input type -> Scan for markers -> Find first open task -> Execute task -> Verify -> Mark done/remove -> Save -> Stop
```

## Constraints

- Only one task is executed per invocation
- The first open task (by file path order, then line number) is always selected
- Task execution must be atomic: complete or fail, never partial
- Supported formats: markdown with checkboxes, source code with TODO/FIXME comments
- Each iteration processes exactly one task

## Requirements

- **One at a time**: Only execute ONE task per invocation of this skill
- **Follow specifications**: Execute tasks exactly as described in the task marker
- **Mark progress**: Update the source file or document to mark the completed task
- **Verify**: Task must be verified as complete before marking as done

## Notes

- Execute exactly one task per invocation
- Each iteration executes exactly one task
- Maintain focus on a single unit of work
- The workflow works with both document structure and source code files
- For markdown: only update progress markers, not document structure
- For source code: remove or comment out TODO/FIXME markers upon completion
- Track progress with explicit open/done markers
